# Proposal Attack Criteria

Apply all five criteria to the whole proposal. An emphasis assigns attention, not a smaller scope.

1. **Route and reuse.** Compare credible existing/native routes with the smallest complete solution.
   Find the current owner before recommending a new skill, helper, wrapper or coordinator.
2. **Execution cost.** Compare total work and critical path: dispatches, context loading, repeated
   checks, serial waits and safe overlap. Reuse verified facts without manufacturing independence.
   Separate measured cost from structural inference.
3. **Ownership and completeness.** Prefer one owner and complete consumer migration. Find parallel
   mechanisms, obsolete representations, unfinished ownership moves and producer/consumer gaps.
   Preserve the user's exclusions and apply the supplied target-contract guidance.
4. **Verification value.** Check that verification establishes the requested outcome, resolves
   consequential uncertainty early, covers failure paths and retains useful evidence. Checks are
   redundant only when scope, inputs, purpose and independence are equivalent. Plan review is not
   implementation proof.
5. **Feasibility and constraints.** Trace actual tools, authority, prerequisites, lifecycle, capacity,
   recovery and unsettled user choices. Do not invent execution authority or missing requirements.

A material finding demonstrates a missed requirement, consequential incorrect assumption,
incomplete ownership, infeasible verification or a meaningfully better route. Name the current
route, concrete counterexample/alternative, source evidence, benefit, tradeoff and smallest remedy.
An explicit proposal to revise an owning instruction is not wrong merely because current text
differs; assess the target design and complete callers.

Wording, formatting, equivalent alternatives, hypothetical safeguards and requests to repeat an
existing requirement are nits unless their concrete consequence meets that material threshold.
Nits do not block or reset clean rounds. Do not invent findings to satisfy a quota or reject a
proposal simply because another design is possible. Explain when the current route is preferable.

An original report states its reviewed identities, all-five coverage and attempted counterexamples,
then `CLEAN` or `CHANGES_REQUIRED` with evidence. A raw verdict is not a vote: preserve dissent and
the caller's validated disposition separately for independent acceptance.
