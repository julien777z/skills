# Reusable Rule Reconciliation

The reusable source rules in `.agents/rules/` replace copies in the consumer repositories. Their provider links are generated by Agent Sync. Consumer `project.md` and `operational-profile.md` files retain repository facts, commands, and product decisions.

| Rule | Canonical choice |
| --- | --- |
| `biome` | All four copies matched, so the shared text was retained. |
| `fastapi` | The backend variant added generic route ownership, response, and gateway guidance to the shorter shared version. The contractor variant's fetch-all guidance was already in it. |
| `github` | The shared workflow wording was retained. The merge exception and main-checkout refresh now state the user's current policy; earlier copies disagreed about agent-configuration merges. |
| `global` | The contractor variant contains the shared guidance plus reusable approval, computer-use, and monitoring details. Repo-only details remain in project rules. |
| `http` | Every copy matched. |
| `poetry` | The contractor variant retains the shared wording and recognizes requirements files when scoping work. Local test commands remain repository-owned. |
| `pydantic` | The longer variant adds reusable configuration ownership guidance. |
| `python` | The contractor variant retains the broad shared guidance and extra configuration, naming, and module guidance. Its Python-version rule preserves support for public libraries; the backend-only 3.12 minimum was not applied to every library. |
| `react` | The fuller frontend variant adds reusable reference-data, interface-copy, and dialog guidance. Product names in examples were replaced with generic records. |
| `sqlalchemy` | The longer variant adds the independent commit-boundary exception. |
| `testing` | The contractor variant adds reusable naming and test-configuration guidance. Its existing fixture advice remains the common baseline. |
| `typescript` | The fuller frontend variant extends the shared type guidance with module, function, data-boundary, and comment guidance. |

The canonical files are intentionally shorter than a union of every variant. Several longer variants repeat task-specific skills or prescribe one repository's deployment and test workflow. Those concerns remain with their skill or owning repository. Edit reusable wording in this repository, then verify it in a consumer at the proposed commit.
